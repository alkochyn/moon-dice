# Кубомет для Miro

Панель для настольных ролевых игр прямо на доске Miro: формулы любой сложности, сохранённые броски и общая история
партии.

Главное требование к проекту — **он обязан грузиться**, в том числе у игроков из России. Отсюда все технические
решения ниже.

## Возможности

- **Формулы.** `1d20+1d5+6`, `4d6kh3`, `d20adv`, `1d6!`, `3#1d20+5`, скобки и арифметика.
- **Сохранённые броски.** Личные (живут в браузере и дублируются в доску) и общие для всей доски.
- **История.** Общий журнал партии обновляется у всех в реальном времени; локальная история формул — по `↑`/`↓` в поле
  ввода, как в терминале.
- **Локальный режим.** Если доска недоступна, кубы всё равно кидаются, история пишется локально.
- **Диагностика.** Экран со статусом связи, версией и откликом хостинга — чтобы не выяснять «почему не работает»
  угадайкой.
- Честный генератор: `crypto.getRandomValues` с отбрасыванием хвоста диапазона, а не `Math.random`.

## Почему так устроено

Прямой повод для проекта: предыдущий кубомет не открывался у части игроков. Причина оказалась прозаической — панель
тянула стили с `unpkg.com`, а российские провайдеры с июня 2025 режут трафик Cloudflare до первых 16 КБ. Блокирующий
`<link>` в `<head>` превращал панель в белый экран.

Отсюда правила, которые здесь соблюдаются жёстко:

1. **Ни одного стороннего запроса.** Весь CSS и JS инлайнятся в единственный `index.html` (~40 КБ), иконки — SVG в
   разметке, шрифты системные. Сборка падает, если в бандле появится ссылка на чужой хост: см.
   [scripts/check-bundle.mjs](scripts/check-bundle.mjs).
2. **SDK грузится из кода, а не из `<head>`.** Запрос к `miro.com` может не упасть, а молча зависнуть, поэтому он идёт
   с таймаутом, а при неудаче панель уходит в локальный режим: [src/board/sdk.ts](src/board/sdk.ts).
3. **Офлайн-кэш.** После первой удачной загрузки service worker отдаёт панель даже при недоступном хостинге:
   [public/sw.js](public/sw.js).
4. **Свой сервер без Cloudflare.** См. «Хостинг».

## Разработка

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # тесты движка кубов
npm run build      # dist/index.html + dist/sw.js, с проверкой бандла
```

Панель открывается и обычной вкладкой браузера — без Miro она работает в локальном режиме, это удобно для отладки.

## Синтаксис формул

| Запись | Что делает |
| --- | --- |
| `1d20`, `d20` | один куб |
| `2d6+3`, `1d20+1d5+6` | сумма кубов и модификаторов |
| `(1d6+2)*2`, `1d10/3` | скобки и арифметика, деление округляется вниз |
| `4d6kh3` | бросить 4 куба, оставить 3 лучших |
| `2d20kl1` | оставить худший |
| `d20adv`, `d20dis` | с преимуществом / с помехой |
| `1d6!` | взрывной куб: на максимуме кидается ещё раз |
| `3#1d20+5` | три отдельных броска одной командой |
| `1d20+5 : атака гоблина` | подпись броска после двоеточия |

В разборе броска отброшенные кубы показаны в скобках, а взрывы — через `!`:
`4d6kh3 → [4, 4, (1), 2] = 10`, `1d6! → [6!6!2] = 14`.

## Хостинг

Панель — статика, нужен только HTTPS. Но выбор площадки здесь не вопрос вкуса:

**Подходит:** свой VPS у российского провайдера (Timeweb Cloud, Selectel, reg.ru) + nginx + свой домен + Let's Encrypt.
Доступен и из России, и из-за рубежа, никем не режется, полностью под контролем. Пример конфига —
[deploy/nginx.conf](deploy/nginx.conf).

**Не подходит:** Cloudflare Pages, Vercel, Netlify и всё остальное за Cloudflare — именно этот трафик и режется.
Hetzner и DigitalOcean тоже под троттлингом.

**Зеркало:** GitHub Pages (за Fastly, а не Cloudflare) деплоится автоматически из
[.github/workflows/deploy-mirror.yml](.github/workflows/deploy-mirror.yml). Держим как запасной адрес.

### Перед выбором хостинга — замерить

В сборку входит [public/probe.html](public/probe.html): страница проверяет, какие хосты открываются у конкретного
игрока (Miro, SDK, этот хостинг, Cloudflare-эталон), и собирает отчёт в одну кнопку. Попросите игроков, у которых
«не грузится», открыть `/probe.html` и прислать отчёт — станет видно, что именно блокируется.

### Выкладка

```bash
cp .env.deploy.example .env.deploy.local   # прописать хост и путь
npm run build
./scripts/deploy.sh
```

## Подключение к Miro

Чужое приложение из маркетплейса нельзя перенаправить на свой хостинг — нужно завести своё.

1. **Команда разработчика.** В Miro создайте Developer team: в такой команде приложение работает без ревью
   маркетплейса.
2. **Создать приложение.** Профиль → *Your apps* → *Create new app*, выбрать созданную команду.
3. **Настроить:**
   - *App URL* (`sdkUri`) — адрес панели. Для разработки годится `http://localhost:3000`.
   - Иконка и название.
   - Разрешения: `boards:read` и `boards:write` — без записи не будет общего журнала и общих пресетов.
   - Включить Web SDK v2 и отображение приложения на доске.
4. **Установить:** *Install app and get OAuth token* → выбрать команду, где лежит игровая доска. Ставит владелец доски,
   остальным игрокам делать ничего не нужно — приложение появится у всех участников.
5. **Зеркало:** заведите второе приложение «Кубомет (зеркало)» с адресом GitHub Pages. Если основной домен станет
   недоступен, партия переключается на него за минуту.

Приложение открывается кликом по иконке в тулбаре: фоновый экземпляр панели вешает обработчик и открывает панель тем
же файлом с `?panel=1`.

## Как хранятся данные

Своего сервера у проекта нет — всё лежит в хранилище доски (`miro.board.storage`, коллекция `dice.v1`) и в
`localStorage`:

| Что | Где | Примечание |
| --- | --- | --- |
| Общий журнал бросков | ключ `log` на доске + копия в браузере | `onValue` прилетает всем клиентам доски, лента живая |
| Общие пресеты | ключ `presets.shared` | редактирует любой участник |
| Личные пресеты | `localStorage` + ключ `presets.user.<id>` | при расхождении побеждает более свежая копия |
| История формул | `localStorage` | навигация `↑`/`↓` |

Журнал ограничен 200 записями. Одновременные броски разных игроков сводятся по `id` записи, запись в доску идёт с
повторами — подробности в [src/board/storage.ts](src/board/storage.ts).
