# Кубомет для Miro

Панель для настольных ролевых игр прямо на доске Miro: формулы любой сложности, сохранённые броски и общая история
партии.

Главное требование к проекту — **он обязан грузиться**, в том числе у игроков из России. Отсюда все технические
решения ниже.

## Возможности

- **Формулы.** `1d20+1d5+6`, `4d6kh3`, `d20adv`, `1d6!`, `3#1d20+5`, скобки и арифметика.
- **Сохранённые броски.** Личные (живут в браузере и дублируются в доску) и общие для всей доски.
- **Внешность игрока.** Имя персонажа, значок и цвет — видны всей партии в истории. Пока игрок ничего не выбрал,
  значок и цвет выводятся из его id, так что все с самого начала различимы.
- **История.** Общий журнал партии обновляется у всех в реальном времени; локальная история формул — по `↑`/`↓` в поле
  ввода, как в терминале.
- **Локальный режим.** Если доска недоступна, кубы всё равно кидаются, история пишется локально.
- **Диагностика.** Экран со статусом связи, версией и откликом хостинга — чтобы не выяснять «почему не работает»
  угадайкой.
- Честный генератор: `crypto.getRandomValues` с отбрасыванием хвоста диапазона, а не `Math.random`.

## Почему так устроено

Повод для проекта: предыдущий кубомет не открывался у одного из игроков партии. Первая версия — что виноват
блокирующий `<link>` на `unpkg.com` (Cloudflare, трафик которого российские провайдеры с июня 2025 режут до первых
16 КБ) — замерами **не подтвердилась**. Пробник [public/probe.html](public/probe.html) показал у игроков из Москвы
другую картину:

- `miro.com` без VPN не отвечает вовсе, запрос висит до таймаута: доска доступна только через туннель, и все играют
  через VPN;
- Cloudflare при этом жив — `unpkg` и `jsDelivr` отвечают за 320–1076 мс;
- GitHub Pages открывается из Москвы напрямую, за 209–242 мс.

То есть сеть панель не ломала, а зависимость от `unpkg.com` осталась миной, которая просто не взорвалась. Причина
у конкретного игрока на момент написания не установлена; наиболее правдоподобные версии — блокировка стороннего
хранилища строгими настройками приватности браузера и раздельное туннелирование VPN.

Правила ниже соблюдаются всё равно — не как лечение известной болезни, а как страховка: каждый лишний внешний хост в
загрузке панели это лишняя точка отказа в сети, которая деградирует без предупреждения.

1. **Ни одного стороннего запроса.** Весь CSS и JS инлайнятся в единственный `index.html` (~160 КБ, в gzip около
   66 КБ), значки игроков — SVG прямо в разметке, шрифты системные. Львиная доля размера это как раз 85 встроенных
   иконок: тянуть их с game-icons.net означало бы ровно ту зависимость от чужого хоста, из-за которой всё началось.
   Сборка падает, если в бандле появится ссылка на чужой хост: см. [scripts/check-bundle.mjs](scripts/check-bundle.mjs).
2. **SDK грузится из кода, а не из `<head>`.** Запрос к `miro.com` может не упасть, а молча зависнуть, поэтому он идёт
   с таймаутом, а при неудаче панель уходит в локальный режим: [src/board/sdk.ts](src/board/sdk.ts).
3. **Офлайн-кэш.** После первой удачной загрузки service worker отдаёт панель даже при недоступном хостинге:
   [public/sw.js](public/sw.js).
4. **Свой сервер без Cloudflare.** См. «Хостинг».

## Разработка

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # тесты движка кубов
npm run build      # dist/index.html + dist/sw.js, с проверкой бандла
```

Панель открывается и обычной вкладкой браузера — без Miro она работает в локальном режиме, это удобно для отладки.

## Синтаксис формул

| Запись | Что делает |
| --- | --- |
| `1d20`, `d20` | один куб |
| `2d6+3`, `1d20+1d5+6` | сумма кубов и модификаторов |
| `(1d6+2)*2`, `1d10/3` | скобки и арифметика, деление округляется вниз |
| `4d6kh3` | бросить 4 куба, оставить 3 лучших |
| `2d20kl1` | оставить худший |
| `d20adv`, `d20dis` | с преимуществом / с помехой |
| `1d6!` | взрывной куб: на максимуме кидается ещё раз |
| `3#1d20+5` | три отдельных броска одной командой |
| `1d20+5 : атака гоблина` | подпись броска после двоеточия |

В разборе броска отброшенные кубы показаны в скобках, а взрывы — через `!`:
`4d6kh3 → [4, 4, (1), 2] = 10`, `1d6! → [6!6!2] = 14`.

## Хостинг

Панель — статика, нужен только HTTPS.

**Основной адрес — GitHub Pages**, деплой автоматический из
[.github/workflows/deploy-mirror.yml](.github/workflows/deploy-mirror.yml). Из Москвы открывается за 209–242 мс даже
без VPN. Ограничение площадки: свои заголовки задать нельзя, там жёстко `Cache-Control: max-age=600`, поэтому новая
версия доезжает до игроков до десяти минут.

**Российское объектное хранилище (Yandex Object Storage, Selectel S3) как запасной вариант не годится**, хотя
напрямую из России отвечает быстро — 312–466 мс. Причина в том, что партия поголовно играет через VPN: у одного из
игроков Selectel через туннель не ответил вовсе, 8 секунд тишины, при живом Yandex Object Storage в том же замере.
У каждого свой провайдер VPN, и часть из них российские хосты не пропускает. GitHub Pages, наоборот, открылся во
всех замерах у всех игроков — и с туннелем, и без.

**Свой VPS + nginx** — если понадобятся свои заголовки, логи и полный контроль. Пример конфига:
[deploy/nginx.conf](deploy/nginx.conf).

**Не годится:** Cloudflare Pages, Vercel, Netlify и всё остальное за Cloudflare.

**Домен стоит купить заранее.** Он развязывает адрес приложения Miro от площадки: переезд станет сменой DNS, а не
переустановкой приложения у всех игроков.

### Замер вместо догадок

В сборку входит [public/probe.html](public/probe.html): страница проверяет, какие хосты открываются у конкретного
игрока — Miro и его SDK, текущий хостинг, Cloudflare как эталон, кандидаты на переезд, — и собирает отчёт в одну
кнопку. Там же игрок отмечает, включён ли VPN: замер через туннель показывает сеть VPN-сервера, а не провайдера,
и без этой отметки отчёт нечитаем.

### Выкладка

```bash
cp .env.deploy.example .env.deploy.local   # прописать хост и путь
npm run build
./scripts/deploy.sh
```

## Подключение к Miro

Чужое приложение из маркетплейса нельзя перенаправить на свой хостинг — нужно завести своё.

1. **Команда разработчика.** В Miro создайте Developer team: в такой команде приложение работает без ревью
   маркетплейса.
2. **Создать приложение.** Профиль → *Your apps* → *Create new app*, выбрать созданную команду.
3. **Настроить:**
   - *App URL* (`sdkUri`) — адрес панели. Для разработки годится `http://localhost:3000`.
   - Иконка и название.
   - Разрешения: `boards:read` и `boards:write` — без записи не будет общего журнала и общих пресетов.
   - Включить Web SDK v2 и отображение приложения на доске.
4. **Установить:** *Install app and get OAuth token* → выбрать команду, где лежит игровая доска. Ставит владелец доски,
   остальным игрокам делать ничего не нужно — приложение появится у всех участников.
5. **Зеркало:** заведите второе приложение «Кубомет (зеркало)» с адресом GitHub Pages. Если основной домен станет
   недоступен, партия переключается на него за минуту.

Приложение открывается кликом по иконке в тулбаре: фоновый экземпляр панели вешает обработчик и открывает панель тем
же файлом с `?panel=1`.

## Как хранятся данные

Своего сервера у проекта нет — всё лежит в хранилище доски (`miro.board.storage`, коллекция `dice.v1`) и в
`localStorage`:

| Что | Где | Примечание |
| --- | --- | --- |
| Общий журнал бросков | ключ `log` на доске + копия в браузере | подписка `onValue` плюс опрос раз в 4 секунды |
| Имя, значок и цвет игрока | `localStorage`, копия в каждой записи журнала | у остальных доступа к чужим настройкам нет |
| Общие пресеты | ключ `presets.shared` | редактирует любой участник |
| Личные пресеты | `localStorage` + ключ `presets.user.<id>` | при расхождении побеждает более свежая копия |
| История формул | `localStorage` | навигация `↑`/`↓` |

Журнал ограничен 200 записями. Одновременные броски разных игроков сводятся по `id` записи, запись в доску идёт с
повторами — подробности в [src/board/storage.ts](src/board/storage.ts).
